# Приёмка VPNN

Матрица ниже относится к новому прогону кандидата. У всех строк исходный статус **NOT TESTED**. Сценарий принимается в указанной среде, для конкретных SHA пакета и конфигурации, сетевого профиля и семейства IP. Для каждого применимого сочетания заполнить [карточку результата](result.md). Для egress и измерений использовать [протокол](measurement.md).

Основание — [план P0, P2, P3, P6-E, P7](../specs/2026-11-03/06-IMPLEMENTATION-PLAN.md), [сверка P0](../specs/2026-11-03/07-P0-P1-EXECUTION.md), [отчёт P1](../specs/2026-11-03/09-P1-APPROVED-ROLLOUT-RESULT.md) и [отчёт P2](../specs/2026-11-03/11-P2-SPRINT-RESULT.md).

## Матрица

| ID | Где и с каким маршрутом | Действие и критерий PASS |
| --- | --- | --- |
| NET | Windows и Honor, домашняя Wi-Fi и целевая операторская сеть (Windows через согласованное подключение), IPv4 и IPv6 отдельно | До, во время и после туннеля записать доступность ICMP, TCP, TLS, UDP и DNS для разрешённых целей. Для каждого протокола указать наблюдение и ожидаемую политику. Для IPv6 проверить требуемый туннель или блокировку и отсутствие обхода. Недоступное в сети семейство оставить NOT TESTED для проверки туннелирования. |
| WIN | Физический Windows, Direct как контроль, отдельно VK, DNS и Auto | Владелец запускает кандидат вручную. Независимый процесс без настроенного прокси подтверждает системный захват и egress. Проверить один TUN, IPv4/IPv6, DNS, Stop во время подключения и после ready, возврат маршрутов и ожидаемый обычный доступ после Stop. SOCKS-проба идёт отдельной строкой. |
| HON | Физический Honor, Wi-Fi и SIM, VK, DNS и Auto | Независимый клиент подтверждает egress. Проверить Wi-Fi → SIM → Wi-Fi, сон/Doze и восстановление при отказе маршрута во сне. Зафиксировать настройки энергосбережения, длительность сна, расход батареи за равное окно с контрольным прогоном, время восстановления и Stop из UI и системного действия. Смена сети после Stop не поднимает туннель. |
| AUTO | Эмулятор synthetic, затем Windows и Honor с назначенными маршрутами | Только назначенные поддерживаемые профили в UI. Первый путь недоступен, резерв подтверждён внешним HTTPS, UI показывает фактический путь. Один TUN, ограниченный перебор, cooldown и last-good в текущей сети. Stop, ручной выбор и смена сети отменяют старый результат, полный отказ виден пользователю. |
| CFG | VK и DNS по отдельности, реальный транспорт, изолированная блокировка прямого IP | Действительный кэш поднимает путь, новая подписанная версия получена через него и сохраняется после перезапуска. Отдельно проверить неверную подпись, expiry и replay. Для согласованного отзыва проверить исчезновение серверных прав и потерю egress, затем отдельно доставку подписанного receipt с указанием пути, очистку кэша и отказ при replay. |
| VK | Реальный VK TURN, эмулятор отдельно от Windows/Honor | С заблокированным прямым путём подтвердить независимый VPS egress, полезный upload/download, восстановление при обрыве, число ready-сессий и влияние параллельных потоков. |
| DNS | Реальный MasterDnsVPN, эмулятор отдельно от Windows/Honor | Та же проверка egress с разрешённым путём через резолвер. Отдельно A/B/A сравнить один набор настроек, записать счётчики DNS и влияние на интерактивный трафик. Loss/reorder/latency с fake resolver маркировать synthetic. |
| SFU | Telemost и WB Stream по отдельности, сначала стенд, затем согласованный VPS и физический Honor | Подтвердить headless Creator на VPS, Joiner на клиенте и передачу полезных данных при запрете прямого TCP/UDP. Проверить HTTPS egress, реконнект, изоляцию устройств и ресурсы по списку ниже. |
| CAP | Согласованный VPS, VK, DNS, смешанный и отдельно каждый SFU | CAP-01–05 по методике. Зафиксировать последнюю полностью пройденную ступень и причину остановки. |
| SOAK | Согласованный VPS и поддерживаемые клиенты | 2 ч, затем 24 ч смешанного использования. Проверить refresh/limit/revoke, отсутствие роста памяти/FD, восстановление после обрывов и restore dry-run. Реальный restore проверяется отдельно. |
| PKG | Windows ZIP и Android APK | Подписи, SHA-256, состав и размеры до/после, лицензии, known-secret scan и candidate manifest. Проверить миграцию старого APK с доступом и кэшем, наличие прежней сборки и сценарий возврата. |

Прогон P1 был реальным VK/DNS на AVD, включая egress до отзыва. Сетевой сценарий и финальный APK после исправления индикатора проверены на разных SHA. Доставка receipt в P1 выполнялась через direct после отключения VPN и снятия правила. Прогон Auto P2 использовал два искусственных профиля, а Windows ZIP проверялся как архив. Эти результаты хранить как исторические ссылки с соответствующей областью доказательства. Полевые ячейки Windows, Honor и операторской сети остаются открытыми.

## SFU и сравнение

Для P6-E завести отдельную карточку на каждый сценарий и провайдера. Зафиксировать роли Creator/Joiner и жизненный цикл, блокировку direct, полезную передачу и egress, обрыв и зависание, смену сети, несколько устройств, лимиты сессий и параллельных проверок, пределы очередей и буферов, справедливость, бюджет CPU/RAM на сессию, контролируемый Stop и освобождение ресурсов, отзыв, просрочку и неверную подпись. После получения исходного ТЗ сопоставить карточки с его 14 идентификаторами и выпустить ведомость PASS/FAIL/NOT TESTED. В репозитории исходное ТЗ отсутствует, формальная ведомость по нему остаётся открытой. Для gate расширения P6 требуется минимум один подтверждённый новый SFU.

| Маршрут | Назначение в сравнении | Полевой статус нового прогона |
| --- | --- | --- |
| VK TURN | Контроль relay | NOT TESTED |
| MasterDnsVPN | DNS-контроль | NOT TESTED |
| Telemost | SFU, отдельно DataChannel и VP8/RTP при наличии | NOT TESTED |
| WB Stream | SFU, зафиксировать требования к видеотреку | NOT TESTED |
| Slipstream | DNS-эксперимент, сравнить с MasterDnsVPN в одинаковой сети и с тем же бюджетом DNS-запросов | NOT TESTED |

В сравнении заполнить DL/UL, RTT/TTFB, ошибки, DNS-запросы на MB (где применимо), CPU/RAM/FD на клиенте и VPS, время восстановления и максимальную подтверждённую ступень. Для каждого адаптера сохранить закреплённую ревизию, вариант сборки и команды запуска, диагностики и отката с плейсхолдерами для доступа. Сравнивать только сопоставимые прогоны.

## Входные данные от владельца

- Физические Windows и Honor с подходящими сборками и SHA-256, SIM и доступ к целевой сети и контрольному Wi-Fi. Запуск и Stop на Windows выполняет владелец.
- Отдельные ограниченные тестовые назначения для каждого устройства и разрешённые цели/резолверы. Для SFU — согласованные тестовые комнаты и роли. Секреты передаются вне Git и отчёта.
- Согласованное окно и лимиты пилота, read-only телеметрия VPS, ожидаемые IPv4/IPv6 egress и независимый HTTPS-наблюдатель с возможностью сверки проб.
- Исходное ТЗ SFU с 14 критериями и доступный комплект для отката.
