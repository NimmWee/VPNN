# 03. Пользовательский клиент, автоматизация и протоколы

Статус: спецификация предлагаемого продукта. База — проверенный локальный кандидат 0.1.4+5.

## Две сборки

Рекомендуется общий репозиторий и общий сетевой слой с двумя вариантами сборки: VPNN для пользователей и VPNN Admin для владельца. Альтернативы: скрытие расширенного режима в одном приложении проще, но не убирает зависимости; независимый форк позволяет радикальную переделку, но удваивает сопровождение исправлений. Выбраны две сборки, не два независимо развивающихся ядра.

Пользовательский пакет сохраняет существующий application ID и сертификат, чтобы обновляться поверх текущего без потери доступа. Admin при необходимости параллельной установки получает отдельный ID и собственное enrollment; секреты между приложениями автоматически не копируются. Скрытая панель не является защитой серверных прав. Административные credentials не включать ни в один бинарник.

| ID | Требование | Критерий |
| --- | --- | --- |
| UX-01 | Первый запуск: вставить ссылку, QR или импортировать пакет | Нет необходимости JSON/YAML-редактирования |
| UX-02 | Главный экран: статус, подключение, способ, автоматический резерв | Доступные способы берутся из назначения, отсутствующие скрыты |
| UX-03 | Автоматически — рекомендуемый режим | Работает без ручного выбора протокола; явно показывает фактический способ |
| UX-04 | Удалить расширенную панель из пользовательской навигации | Нельзя открыть через старый маршрут/deep link |
| UX-05 | Помощь | Обновить настройки, безопасный отчёт, версия, удалить доступ |
| UX-06 | Состояния | Нет сети / настройки устарели / нет доступного пути / доступ отозван различимы |
| UX-07 | Компактность | Отчёт состава APK/ZIP до/после; удалить неиспользуемые ресурсы только с проверкой сборок |
| UX-08 | Доступность | Масштаб текста, screen reader, тёмная тема, локализация новых строк |

Не показывать пользователю окна ARQ, количество TURN сессий, адрес резолвера, Core и внутренние порты. «Прямой VPN» не называть «без VPN»: это защищённый профиль непосредственно к серверу.

## Автоматический выбор

Существующий резерв direct/VK/DNS расширить общей моделью профиля: `id`, `kind`, `priority`, `capabilities`, `minimumClientVersion`, `enabled`. Поля вводить совместимо; не переименовывать старый `direct` без миграции. Несколько обычных профилей нельзя помещать в один неразличимый hardcoded ID.

Алгоритм: последний пригодный для текущей сети способ → назначенные быстрые прямые профили (AWG/обычный) → VK → DNS. Порядок задаётся администратором; при известных белых списках бессмысленный direct не должен каждый раз задерживать запуск. Все попытки ограничены общим временем, а тяжёлые транспорты запускаются последовательно.

- Проверять реальный HTTPS через выбранный путь, с актуальной generation сети/профиля/TUN.
- Сохранять текущий маршрут при единичной ошибке; подтверждать отказ несколькими пробами. Ошибка одного проверочного сайта не равна отказу всего интернета.
- Cooldown неудачного пути; не переключаться постоянно между двумя нестабильными путями.
- Смена сети/ручной выбор/Stop отменяют старые попытки и ответы.
- Возврат на более быстрый путь — после устойчивого подтверждения, с учётом разрыва активных соединений. Сохранение звонка/загрузки при смене протокола не обещать.
- Отзыв/подпись/истечение — не сетевые ошибки и не разрешение пробовать устаревший профиль.
- Базовое поведение после исчерпания резервов сохранить: остановить туннель, сообщить, что обычный интернет может продолжить работать. Kill switch — отдельная явная опция с платформенными тестами, не скрытая смена поведения.
- Фон Android проверяется системным сервисом с учётом Doze; не объявлять UI-таймер достаточным для устойчивости в фоне.

Приёмка AUTO: отказ старта, отказ после подключения, CAPTCHA, два ложных health failure, ручной Stop в каждом этапе, смена Wi-Fi/сотовой сети, suspend/resume, все пути исчерпаны, захват TUN отказал, профиль обновлён во время переключения. В каждый момент один владелец TUN.

## AmneziaWG

Локальный `client/core/Clash.Meta/adapter/outbound/wireguard.go` содержит AmneziaWG options и разные реализации; это техническая основа, не приёмка interoperability. [Официальный amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go).

AWG-01: выбрать и зафиксировать совместимую версию сервера/клиента и набор параметров. Новые параметры v3 нельзя считать совместимыми со старой конфигурацией только по названию протокола.

AWG-02: per-device ключи и IP, генерация приватного ключа на устройстве предпочтительна; на сервере публичный ключ и назначенные адреса. Если нужен импорт существующего профиля — безопасный vault, без логов и общего ключа на группу.

AWG-03: серверная выдача/отзыв/ротация через reconciler, без второй VPS, без перезапуска чужого legacy WG. Определить отдельный интерфейс/порт, правила маршрутизации и обратного пути на подготовительном серверном этапе.

AWG-04: использовать существующий Core outbound под одним системным TUN. Защитить внешние сокеты от петли. UDP, MTU, IPv6, DNS, смена сети, keepalive и расход батареи обязательны к тесту.

AWG-05: для полностью blocked-IP этот профиль должен быстро уступать relay. AWG поверх VK UDP возможен только отдельным экспериментом совместимости, не заменой текущего TCP bonding.

## Обычные профили и управление

PROTO-01: типизированный импорт VLESS/Reality и AWG; затем добавлять только реально используемые Trojan/Shadowsocks и др. Проверка до публикации, запрет неподдерживаемых полей и небезопасных endpoint.

PROTO-02: XHTTP и TrustTunnel уже представлены в исходниках mihomo; включать управляемый профиль только после клиента/сервера E2E. XHTTP за доступным edge — отдельный вариант от XHTTP напрямую на заблокированном IP.

ADMIN-01: группы, назначение, срок, отзыв, версия опубликована/применена/получена. Обновление состава пользователей не должно необоснованно обрывать всех. Нужен staged validate → atomic apply → acknowledge; при невозможности hot reload честно обозначать окно переподключения.

ADMIN-02: сохранять fail-closed отзыв; разделить ошибки необязательной публикации зеркала и ошибок применения прав, чтобы недоступность зеркала не выключала весь data plane.

## Поставка

Фиксировать pinned источники, лицензии и совместимость локальных патчей. Сначала анализ размера: Flutter, Core, дополнительные библиотеки, assets, ABI. Скрытие экранов не гарантирует уменьшения native библиотеки. Цель первой итерации — не увеличить пакет без обоснования; численный целевой размер принять после отчёта состава. APK по ABI, полный Windows комплект, SHA-256, подписи, rollback. В будущем подписанное обновление приложения отдельно от конфигурации; TUF-подобная защита версий не заменяет платформенную подпись.
