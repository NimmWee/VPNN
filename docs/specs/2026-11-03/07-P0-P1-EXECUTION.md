## P1

Статус первого прогона: локальная реализация и unit/integration проверки выполнены. В продолжении ниже добавлены сборка Android, read-only SSH и настоящие VK/DNS проверки. Gate новой версии и подписанного отзыва ещё открыт. Публикации не было.

### Реализовано

- `config_transport.dart`: явный direct или HTTP proxy Core, TLS verification независимо от общего переключателя проверки сертификатов, no redirects, 1 500 000 байт, ограниченные таймауты, закрытие активного запроса.
- Для VK/DNS `profile_update.dart` добавляет loopback HTTP listener `127.0.0.1:19094` с `proxy`, указывающим непосредственно на единственный embedded outbound. Правила `MATCH,DIRECT` и общий режим Core не выбирают маршрут этого listener. Общий mixed-port используется только для managed direct. Ошибка listener не включает прямой fallback. При занятом порте требуется устранить конфликт; приложение не останавливает посторонний процесс.
- `provider.dart` выбирает маршрут по работающему managed-профилю. Если другой профиль уже работает, запрос завершается ошибкой вместо предположения о его маршруте. При отсутствии работающего соединения остаётся bounded direct-запрос. Новый второй владелец TUN не создаётся.
- `repository.dart`: общий deadline refresh ≤30 секунд, включая validation; максимум 3 endpoints; отмена сетевой операции и отклонение поздних результатов при Stop/dispose/таймауте. JSON передаётся в isolate через отдельную функцию, без захвата HttpClient.
- Зашифрованный write-ahead journal перед сохранением version floor и кэша. После прерывания записи load повторно проверяет подпись, устройство, срок и версию и завершает commit. Подтверждённый отзыв удаляет основной кэш и журнал, сохранённый revoked marker блокирует replay.
- Schema1 сохранена. Необязательные подписанные `controlEndpoints` (1–3 безопасных origins) заменяют только адреса API, сохраняя ключ, устройство и token. `refreshAfter` проверяется внутри интервала issuedAt/expiresAt. Старые schema1 без этих полей принимаются.
- `refresh_policy.dart`: предварительное обновление (не позже примерно 6 часов при обычном 7-дневном пакете), backoff 30 секунд…30 минут с ±10% jitter; опрос контроллера раз в 2 минуты. Успешное обновление сбрасывает backoff. Сохранённый high-water времени не позволяет откатом часов продлить кэш; откат более 5 минут возвращает expired, меньший использует сохранённое время. Это локальная защита, не независимый источник времени.
- Изменение/сокращение или приближение срока установленного профиля проверяется перед применением. Нужная перезагрузка проходит через существующего владельца соединения даже при неизменном тексте профиля; свежие одинаковые профили переиспользуются.
- Диагностика содержит версию и категорию маршрута, без endpoints, токенов и ссылок звонка.

### Проверяемый отзыв и серверная совместимость

Локальный control выдаёт для известного отключённого устройства подписанный ответ 403 при наличии `X-VPNN-Nonce` (32 случайных байта). Подписаны schema/kind/deviceId/version/issuedAt/expiresAt/nonce; окно ответа — 5 минут. Клиент проверяет подпись прежним ключом, устройство, nonce текущего запроса, floor версии и срок. Неподписанные 401/403, HTML и 407/ошибки proxy не стирают кэш.

Для старых клиентов control сохраняет прежний неподписанный 403 при отсутствии корректного nonce. **Новый клиент со старой рабочей панелью получает network на её неподписанный 403**, поэтому мгновенная локальная очистка по отзыву требует согласованного обновления control. Серверный data-plane отзыв этим не меняется. До согласованного серверного этапа новую сборку не считать готовой к выпуску.

Локальный control также добавляет refreshAfter = issuedAt +6 часов и подписанный controlEndpoints из настроенного PublicURL. Серверные файлы менялись только в C:/VPNN/control; на VPS не копировались и службы не перезапускались.
