# 02. Актуальность ссылки и восстановление настроек

Статус: предложение к реализации. Цель: одна выдача доступа пользователю, автоматическое обновление при наличии любого пригодного пути, понятное восстановление без ослабления подписи и отзыва.

## Что означает постоянная ссылка

Приглашение VPNN идентифицирует доступ, а не навсегда фиксирует IP, звонок VK и все секреты. Адрес панели и список способов могут меняться в подписанных настройках. Ссылка звонка живёт по правилам VK; TURN-реквизиты имеют отдельный короткий срок. В 0.1.4 реквизиты кэшируются в памяти по серверному сроку с запасом, максимум 8 часов; после перезапуска требуется новая авторизация. Не обещать вечный звонок или отсутствие CAPTCHA навсегда.

Если нет ни одного доступного внешнего пути, приложение не может получить новые данные. Если VPS выключена, VK/DNS к той же VPS не восстановят её. Это явно разные ошибки интерфейса.

## Требования

| ID | Требование | Приёмка |
| --- | --- | --- |
| CFG-01 | Начальная настройка без API | Чистый клиент импортирует подписанный пакет и подключает DNS/VK при заблокированном IP панели |
| CFG-02 | Обновление через работающий путь | Прямая панель недоступна; через VK, затем отдельно DNS получена новая подписанная версия |
| CFG-03 | Предварительное обновление | При доступной связи не дожидаться истечения 7 суток; удерживать пригодный последний пакет |
| CFG-04 | Безопасная смена endpoints | Новый список подписан прежним доверенным ключом; произвольные URL из сети не принимаются |
| CFG-05 | Независимое зеркало | Компрометация зеркала не раскрывает настройки и не позволяет подмену/откат |
| CFG-06 | Ротация VK | Новая собственная ссылка проверяется до назначения основной; рабочая старая сохраняется на ограниченный переходный период |
| CFG-07 | Отзыв | Подтверждённый отзыв запрещает возврат к кэшу/зеркалу; сетевой 403 CDN не становится ложным отзывом |
| CFG-08 | Ротация доверия | Замена ключей с цепочкой доверия и аварийным восстановлением; новый ключ из случайного зеркала не принимается |
| CFG-09 | Сроки и часы | Откат часов/версии, истёкший пакет и устаревшее зеркало не продлевают доступ |
| CFG-10 | Ограниченность | Общий deadline обновления, предел размера, запросов и попыток; отмена при новом пользовательском намерении |

## Рекомендуемая схема v1

1. Первичная выдача: существующий offline bootstrap-файл через доверенный канал, рядом обычная ссылка/QR для удобства. QR должен содержать небольшой указатель или компактный пакет только если помещается; не обещать запихнуть мегабайтный файл в QR.
2. При запуске проверить подпись, device ID, срок и минимум версии сохранённой конфигурации. Если она действительна, можно начать соединение без обязательного успешного API-запроса.
3. Сначала уже работающий маршрут, затем ограниченная прямая попытка при отсутствии маршрута; при неудаче подключить доступный сохранённый VK/DNS-профиль через штатного владельца.
4. Запросить HTTPS API **явно через подтверждённый выбранный маршрут**. Реализовать абстракцию транспорта обновления; не полагаться на предположение, что Dart HTTP автоматически попал в TUN. Проверять собственным серверным маркером/журналом без токенов и изолированным запретом direct egress.
5. Валидировать полный пакет, записать атомарно вместе с версией, применить только нужные изменения. Получение настроек не должно разрывать неизменившийся рабочий профиль.
6. После подключения проверять актуальность; в рабочем состоянии предложенный период 6 часов ±20% jitter, перед истечением — чаще в пределах общего бюджета. После ошибки backoff 30 секунд → 2 → 10 → 30 минут, без фонового бесконечного опроса при полном отсутствии сети. Числа — начальная политика для испытаний, не уже реализованные параметры.
7. Если пакет истёк, не запускать по нему обычный трафик. Пытаться получить новый через доступный API/зеркало или предложить импорт свежего файла. Специальный ограниченный recovery-доступ по истёкшему профилю — отдельная v2, только с серверным ограничением назначения и срока; в v1 его нет.

Парадокс первого подключения решается стартовым пакетом: для получения DNS/VK-настроек нельзя требовать предварительно уже работающий DNS/VK. Приложение без стартовых данных и без доступного API само этот круг не разорвёт.

## Зеркало: второй этап, не обязательный отдельный VPS

Разрешённое объектное хранилище/CDN может отдавать небольшой зашифрованный пакет. Доступность домена и IP проверять из целевых сетей; принадлежность хостинга VK/Яндексу не означает попадание адреса в белый список. Два имени на одной VPS не дают независимость от IP-блокировки.

Предложенная оболочка: `schema, deviceBinding, revision, issuedAt, refreshAfter, expiresAt, keyId, ciphertext, nonce, signature`. Подпись покрывает все поля. Семантика и формат фиксируются отдельными тестовыми векторами; перед миграцией определить каноническое представление подписываемых байтов. Шифрование AEAD индивидуальным ключом восстановления либо публичным ключом устройства; выбранный вариант согласовать с текущей выдачей bearer invitation. Нельзя публиковать обычный подписанный plaintext bootstrap: подпись не скрывает токен и ключи.

Зеркало получает только ciphertext и минимальные метаданные. Основной API bearer token туда не отправляется. Ссылки зеркала без секретов в query/log/referrer, redirects запрещены; путь только из подписанного списка. Отдельный счётчик revision для пакета доставки предотвращает заморозку старого срока при неизменной версии профилей. При повторном пакете запрещено сдвигать expiresAt локально.

Сначала один авторитетный API и один опциональный независимый канал; не плодить много секретных копий. Пакет целевого размера ≤32 КиБ для обычной группы; текущие жёсткие лимиты остаются верхней защитой. На 1 Мбит/с 32 КиБ теоретически передаются за 0,262 секунды без RTT/TLS/потерь: даже медленный DNS пригоден для обновления настроек. Реальное время измерить.

Истечение/rollback/подпись/ротация доверия проектируются с учётом [TUF specification](https://theupdateframework.github.io/specification/latest/); это использование принципов, не заявление о полной TUF-совместимости.

## Смена звонков и отзыв

- Хранить максимум основной и один резервный собственный звонок с generation; не использовать чужие публичные конференции.
- Новый звонок проверить ограниченной авторизацией и передачей, затем публиковать. Не создавать браузерного постоянного участника без доказанной необходимости.
- Обновление нового звонка доставлять также через DNS; две ссылки одного сервиса не независимы от общей недоступности VK API.
- Срок cache TURN не равен сроку ссылки, профиля или прав устройства.
- Для одновременного истечения credentials использовать jitter, single-flight и backoff; не обходить CAPTCHA/rate limit серией аккаунтов.
- Серверный отзыв действует независимо от клиентского знания. Целевой срок применения исправного reconciler ≤30 секунд, подтвердить измерением. При offline-клиенте мгновенно узнать отзыв невозможно.
- Авторитетный отзыв должен быть аутентифицирован; подписанное сообщение предпочтительно для многоканальной доставки. Отзыв из primary API сохраняется как tombstone, устаревшее зеркало его не отменяет.

## Обязательные сценарии

Первый запуск без API с файлом; запуск с кэшем 6 дней; истёкший кэш 8 дней; обновление через VK и DNS при blocked direct; старый/поддельный/чужой пакет; повреждённый cache; смена ключа; неверные часы; смена панели; зеркальный 403/HTML/oversize; отзыв и replay; отзыв во время обновления; перезапуск в момент записи; смена сети и отмена; все пути недоступны. В отчётах только версии, возраст, источник-категория, ошибки и длительности, без адресов звонка и секретов.
