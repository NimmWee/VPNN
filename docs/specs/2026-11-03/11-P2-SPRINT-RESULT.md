# P2. Пользовательская сборка и Auto

В VPNN пользователь видит только назначенные и поддерживаемые маршруты, Auto и фактический маршрут подключения. Обновление настроек, импорт, удаление доступа, версия и безопасный диагностический отчёт доступны с главного экрана. Приглашение можно вставить или открыть ссылкой. Существующий расширенный интерфейс доступен в сборке с `VPNN_ADMIN=true`.

Старые назначения direct, VK и DNS сохраняют совместимость. Подписанные настройки поддерживают отдельные ID, тип, приоритет, доступность, capabilities и минимальную версию клиента. Неизвестные типы и отключённые профили исключаются из выбора. Реестр управляемых профилей позволяет удалить назначенные записи при отзыве и сохранить остальные профили.

Серверу следует выдавать новые ID только устройствам с обновлённым клиентом. Версия 0.1.4 принимает только старые ID direct, vk и dns. Проверка обновления APK использовала именно такой пакет настроек.

Auto предпочитает последний рабочий маршрут в текущей сети, затем проверяет назначенные пути по приоритету. Попытки ограничены по времени, один маршрут не повторяется в одном переборе. Неудачный маршрут временно исключается. Stop, ручной выбор и событие смены сети отменяют устаревшие операции. Для готовности требуются подтверждение транспорта и HTTPS через ядро. Одиночная отрицательная проверка при работающем туннеле сохраняет текущий путь.

## Локальные проверки

- 133 целевых Flutter-теста, два теста навигации с флагом Admin и статический анализ прошли. Покрыты миграция выбора, подпись и кэш, cooldown, отказ захвата, отсутствие ответа от службы, неизвестный результат HTTPS, задержанный старт, Stop и устаревшие ответы.
- Проверка виджета в тёмной теме с текстом 200% подтвердила, что видны только назначенные маршруты, а Auto и ручной выбор доступны через семантику кнопок.
- В Android API 35 импортирован подписанный тестовый пакет. Первый SOCKS-маршрут был недоступен, Auto выбрал рабочий резерв. Итоговый отчёт показывает `ready`, `captureReady: true`, `coreProbeReachable: true` и `usedFallback: true`. Главный экран показал имя резерва и включённый туннель. Проверка доступна в `logs/p2-final-emulator-ready.json`.
- Обновление подписанных настроек через активное подключение прошло на локальном стенде. Локальный API принял два авторизованных запроса за прогон.
- Android сохранил TUN при выключенном экране и принудительном глубоком Doze. Отдельный процесс в эмуляторе выполнил HTTPS-запрос. После смены сети Auto восстановил подключение. Stop с экрана и через системное быстрое действие остановил VPN. После изменения Wi-Fi соединение оставалось выключенным.

Эмулятор использовал два искусственных прямых профиля. Рабочие VK/DNS в P2, Android на Honor с SIM, длительный сон и системный трафик Windows IPv4/IPv6 требуют полевой приёмки. Проверка Doze подтверждает сохранение активного туннеля и доступность в этом прогоне. Переключение на резерв при отказе в длительном Doze не проверено.

Тест `test/lint/typography_test.dart` отдельно выявил существующую ошибку нормализации путей на Windows. Локальная копия проверки с нормализацией разделителей прошла.

## Пакеты

Подписанные APK 0.1.6+7 лежат в `artifacts/p2-local`. Для каждой архитектуры подтверждены `space.chichy.vpnn`, прежний сертификат и повышение versionCode. В Android API 35 установлен подписанный x64-пакет 0.1.4+5, импортировано локальное назначение, затем выполнено обновление поверх установки. В 0.1.6 сохранились доступ и офлайн-настройки. На экране остались Auto и назначенный прямой маршрут.

| ABI | APK 0.1.4+5, байт | APK 0.1.6+7, байт |
| --- | ---: | ---: |
| ARM64 | 64 407 863 | 62 270 455 |
| ARMv7 | 64 592 663 | 62 254 783 |
| x64 | 67 175 005 | 65 024 969 |

Admin собран для x64 в debug. Варианты разделены флагом сборки. Отдельный application ID для параллельной установки Admin не введён. APK подготовлены для локальной приёмки, статус публикации в манифесте `published: false`.

Windows x64 собран в release. ZIP содержит `VPNN.exe`, ядро, библиотеки и лицензии. Проверена целостность архива. Его размер 64 337 688 байт против 66 660 269 байт у 0.1.4. Приложение на Windows не запускалось. Состав APK и ZIP до и после сборки записан в `logs/p2-package-comparison.json`. Размеры и SHA-256 всех пакетов записаны в `artifacts/p2-local/MANIFEST.json`.
