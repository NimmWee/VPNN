# Управление администратором — подтверждённый сценарий

Уточнение пользователя 2 ноября 2026: общими звонками, серверами и параметрами занимается администратор. Клиентские приложения получают изменения; пользователям не требуется вставлять ссылку звонка, IP VPS или DNS-ключ вручную.

## Администратор

1. Заходит в защищённую веб-панель.
2. Выбирает группу пользователей, вставляет ссылку своего разрешённого звонка VK и при необходимости резервные ссылки.
3. Назначает группе DNS/VK и обычные профили, публикует изменения.
4. Выдаёт отдельное приглашение устройству. Управляет отзывом и видит подтверждённые версии.

## Пользователь

Один раз добавляет приглашение, затем выбирает разрешённый способ и подключается. Не получает административный токен или пароль VPS. Смена общих параметров выполняется администратором. Локальная кнопка обновления только получает опубликованные настройки.

Клиенты периодически получают подписанные изменения, пока есть доступный путь. Обновление работающего звонка может потребовать переподключения; офлайн-устройство не считается мгновенно обновлённым. Действующий кеш нужен, чтобы запуск DNS/VK не зависел от доступности API до туннеля.

## Реализовано и не закончено

API групп/пула звонков, отдельные токены устройств, подпись и клиентское получение уже есть. Публичная HTTPS-установка панели, удобные формы вместо JSON, подтверждение применения сетевых ключей на VPS и полный сетевой отзыв пока не завершены. Текущие тестовые приглашения используют локальный сервис компьютера; это не окончательная пользовательская настройка.

## Подключение VK-аккаунта

Опциональный следующий этап: проверить возможности исходников проекта Anton48 и поддерживаемой авторизации для создания/обновления собственных звонков. Не считать автоматическое создание уже реализованным. Пользовательский пароль VK не должен передаваться обычным клиентам. Ручная CAPTCHA может требоваться независимо от централизованного управления звонком.

## Текущий Windows-инцидент

В запущенной старой тестовой Windows-сборке было вставлено приглашение эмулятора с API `10.0.2.2:8098`. Для Windows этот адрес недоступен; кеш и профили не появились, туннель не был запущен. Правильное тестовое приглашение находится в `C:\VPNN\private\transport-test\windows-invitation.txt` и указывает на `127.0.0.1:8098`. Его API-ответ, подпись и назначение устройству проверены. Автоматическое редактирование поля через UI не применилось; пользователь получил запрос заменить приглашение вручную. Фактическое Windows-подключение после замены ещё требует проверки.
