# VPNN 0.1.3+4 — локальный кандидат и исследование скорости

Исторические измерения. Сборки этого кандидата удалены. [Актуальные пакеты](../artifacts/p2-local/MANIFEST.json).

Дата: 3 ноября 2026, Asia/Tomsk. Кандидат не опубликован и не заменяет активный 0.1.2+3. Системный VPN рабочего Windows не включался; серверные настройки не менялись. Реальный Honor и МегаФон не испытаны.

## Изменения

- В клиенте показаны этапы получения настроек, выбора режима, создания системного туннеля, запуска транспорта, CAPTCHA и проверки доступа через Core.
- Кнопка экспорта в заголовке сохраняет `VPNN-diagnostics.json`: версия, платформа, этапы и их длительности, код ошибки, состояние захвата и разрешённые числовые счётчики. Нет приглашений, идентичности устройства, ключей, cookie, ссылок звонка и произвольного текста ошибок. История ограничена 32 событиями.
- В статус Core добавлен необязательный объект `counters`. Для DNS доступны UDP-байты/пакеты, исходящие повторные передачи, ошибки записи, переполнение очереди приёма, согласованные MTU, окно и дублирование. Для VK — байты и число готовых/заданных сессий. Это транспортные показатели; они не равны полезному HTTPS-трафику.
- Подготовленное DNS-имя сохраняется между пакетами внутри каждого encode-worker. Содержимое пакета строится заново. Регрессионный тест проверяет обе части поведения.
- Настройки MTU, дублирования, ARQ и шифрования повседневного клиента оставлены прежними. Экспериментальные параметры доступны только измерительной команде, вне подписанной схемы профилей.
- Существующие владелец TUN, ограниченный резерв, отмена и проверка актуальности маршрута сохранены. Остановка после исчерпания резервов проверяется существующим тестом. Системный kill switch не добавлялся.

Проверка Core не является независимым доказательством перехвата браузера/ОС. Экспорт явно содержит `systemEgressVerified: false`. Ожидаемые egress-адреса в подписанную схему в этой итерации не добавлялись.

## Методика

`engine/cmd/vpnn-bench` выполняет ограниченные передачи через явный SOCKS на `127.0.0.1`, либо через текущий маршрут хоста без собственного прокси. Системный proxy и маршруты не меняются, переменные HTTP_PROXY не используются, при отказе SOCKS нет перехода на DIRECT.

Пределы: 3–10 повторов, 1–4 параллельные передачи, до 8 МиБ на передачу и до 60 секунд на неё; общий deadline команды — 12 минут. Redirect не принимается, TLS проверяется штатно, сжатие и повторное использование HTTP-соединений отключены. Короткий ответ не считается успешной передачей заданного объёма. Отдельный `-upload` делает POST на явно указанный endpoint. Синтетический HTTP разрешён только на loopback.

`-expect-ip` проверяет egress через тот же SOCKS до измерений. URL и конфигурация в JSON-отчёт не попадают. `firstByte*` — время до первого байта с установкой соединения/TLS, а не сетевой RTT. `medianMbps` относится к одной передаче; `medianAggregateMbps` — к суммарной скорости параллельного раунда. На трёх повторах p95 является лишь предварительной оценкой.

`tools/benchmark_runner.py` собирает выборочные CPU-seconds и пиковую RSS принадлежащих запуску процессов, сохраняет вывод транспорта только в частный лог и завершает только созданные им процессы. Для VK можно передать частный Xray-конфиг с loopback SOCKS. Требуется `psutil`. Ресурсы VPS и батарея телефона этим стендом не измеряются.

## Результаты исследования

Передачи к HTTPS endpoint Cloudflare выполнены с текущего компьютера. Оператор, ограничения и возможный другой VPN в текущем маршруте хоста не устанавливались. Поэтому это не эталон мобильного интернета и не сравнение с гарантированно чистым ISP-путём.

| Условие | Объём / параллелизм | Медиана Мбит/с | Решение |
| --- | --- | ---: | --- |
| Текущий маршрут хоста, без собственного SOCKS | 256 КиБ / 1 | 2,83 | Контекст, не операторский эталон |
| DNS, штатные параметры, ранний прогон | 256 КиБ / 1 | 1,10 | Исходное наблюдение |
| DNS, штатные параметры | 1 МиБ / 1 | 2,52 | Разброс 1,31–2,95; недостаточно для обещаний |
| DNS, предел download MTU 1000, согласовано 882 | 1 МиБ / 1 | 2,25 | Разброс 1,64–3,77; улучшение не подтверждено |
| DNS, штатные параметры, отдельный контроль | 1 МиБ / 1 | 1,66 | Нужны повторные контролируемые сравнения |
| DNS, дублирование 1 вместо 2 | 1 МиБ / 1 | 0,86 | Отклонено: 5 повторов, TTFB p50 1501 мс |
| DNS, штатные параметры | 256 КиБ / 3 | 0,80 на передачу; 1,93 суммарно | Параллелизм не даёт кратного выигрыша |
| DNS после исправления кэша | 1 МиБ / 1 | 1,58 | Сетевое ускорение не подтверждено; не сравнивать с микротестом |

В контрольном DNS-прогоне: download MTU 500, upload MTU 98, ARQ-окно 600, дублирование 2, ноль исходящих повторов и отброшенных входящих пакетов за наблюдаемый интервал. Согласованный upload MTU меньше исходного предела 150: нужно учитывать длину делегированного имени и протокольные накладные расходы. Увеличение TUN MTU это ограничение не устраняет.

В отдельном контрольном прогоне RSS измерительного процесса достигла около 31,5 МиБ; CPU — около 0,97 секунды за 17,5 секунды запуска. На этом компьютере это не похоже на насыщение CPU; вывод о VPS из этих данных сделать нельзя. При дублировании 1 расход CPU не снизился, а время запуска выросло примерно до 34,8 секунды.

### Подтверждённое локальное улучшение

Три повтора микротеста подготовки DNS-пакета:

| Путь | нс/пакет | байт выделений/пакет | выделений/пакет |
| --- | ---: | ---: | ---: |
| Прежний, без сохраняемых кэшей | 753–782 | 1090 | 8 |
| С повторным использованием кэшей | 543–568 | 544–545 | 5 |

Медианное время этого участка уменьшилось примерно на 28%, выделения памяти — примерно вдвое. Это уменьшает локальные накладные расходы, но не доказывает рост скорости туннеля. Сырые результаты: `logs/planner-cache-before.txt`, `logs/planner-cache-after.txt`.

### VK

Фактический профиль использует TCP поверх TURN/DTLS/KCP/smux, 6 сессий. При обычном режиме одна TCP-передача занимает одну сессию пула; больше сессий не означает автоматического объединения их скорости для одного потока.

Реальная попытка остановилась на ручной CAPTCHA. Обход или автоматическое решение не выполнялись. Поэтому реальная матрица TURN 1/3/6/12 и оценка relay остаются непроверенными. Локальная матрица KCP 1/3/6/12 выполнена по три раза с передачей 256 КиБ на сессию. Она проверяет только тракт KCP/smux в памяти, без TURN, DTLS и сети оператора; цифры не являются скоростью VK. Проверки потерь, пула сессий, TCP/UDP relay и bonding прошли. Bonding не включался ни в одном рабочем профиле.

## Воспроизведение

Из `C:\VPNN`, предварительно собрав `go build -o ..\artifacts\vpnn-bench.exe ./cmd/vpnn-bench` из `engine` после `tools/env.ps1`:

```powershell
python tools/benchmark_runner.py --private-log private/transport-test/new-bench.log --report logs/new-bench.json -- -engine-config private/transport-test/dns-production.json -state-dir private/transport-test/bench-dns -proxy 127.0.0.1:19082 -url 'https://speed.cloudflare.com/__down?bytes=1048576' -expect-ip 89.125.120.163 -bytes 1048576 -timeout 30s
```

Для эксперимента добавить только один параметр: `-dns-download-mtu 1000` или `-dns-duplication 1`. Для параллельного измерения — `-parallel 3`; для upload использовать подходящий endpoint и `-upload`. Каждый запуск должен иметь новое имя отчёта. Эти параметры не публикуются устройствам и не меняют рабочий сервер.

## Проверки и поставка

Доказательства и фактические пропуски фиксируются в `logs/performance-validation.json`. Основные журналы: `performance-flutter-final.txt`, `performance-analyze-final.txt`, `performance-masterdns-final.txt`, `performance-freeturn-tests.txt`, `performance-dns-integration.txt`, `performance-windows-final.txt`, `performance-android-final.txt`.

Пройдены 193 выбранных Flutter-теста и анализатор; тесты engine, полный набор MasterDnsVPN, выбранные FreeTurn/VK/relay/KCP и Go vet, 12 deployment-тестов и 3 теста измерительного runner. Дополнительный Go race-detector не запускался: текущий Windows toolchain настроен без CGO.

Подписанный x64 APK 0.1.3 установлен на отдельный API35-эмулятор. Свежий offline bootstrap импортирован при запрете прямого адреса VPS; DNS передал независимый HTTPS с egress `89.125.120.163`. Отдельная проверка дополнительно запретила HTTPS вне TUN и снова прошла. Экспорт диагностики проверен через настоящий Android file picker: получен JSON с числовыми счётчиками, без заявления о независимой проверке системного выхода. Временный файл отчёта и firewall-правила удалены, приложение остановлено, TUN исчез, созданный эмулятор завершён. Все три APK проверены тем же сертификатом, что у 0.1.2.


Остаются: реальный Windows/Chrome IPv4/IPv6, Honor/МегаФон, батарея и сутки непрерывной работы, реальные VK-измерения после ручной авторизации, память/CPU VPS и ёмкость группы. Чистое восстановление сервера и доставка обновлений в эту локальную итерацию не входят.
