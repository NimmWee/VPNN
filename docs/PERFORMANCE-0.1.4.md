# VPNN 0.1.4+5 — VK Calls, скорость и компактный рабочий каталог

Исторические измерения. Сборки этого кандидата удалены. [Актуальные пакеты](../artifacts/p2-local/MANIFEST.json).

Дата: 3 ноября 2026, Asia/Tomsk. Локальный кандидат Android/Windows. Рабочий системный VPN Windows агент не включал, конфигурацию VPS не изменял.

## Что изменено

1. Первой используется анонимная авторизация VK Calls: `auth.getAnonymToken` → `messages.getCallPreview` → `messages.getAnonymCallToken` на `api.vk.me`, затем получение TURN через OK Calls. Новый путь использует существующие TLS и socket-protection, общий лимит 35 секунд, проверку TLS и ограничение ответа 1 МиБ. Redirect не разрешён; токены и ответы API не выводятся в ошибки.
2. Старый путь с ручной CAPTCHA остаётся резервом при недоступности нового API. Недействительная ссылка, запрет анонимного входа, переполненный звонок и rate limit не запускают перебор альтернативных аккаунтов. CAPTCHA автоматически не решается.
3. Кэш использует срок из TURN username с запасом 60 секунд и верхним пределом 8 часов. Если сервер не сообщает распознаваемый срок, сохранено прежнее ограничение около 9 минут. Просроченные реквизиты не принимаются. Изоляция устройств/звонков, отзыв, инвалидирование и хранение только в памяти сохранены.
4. Для TCP с несколькими сессиями по умолчанию включено существующее объединение каналов `proxy.bond`. Один TCP-поток теперь может использовать несколько готовых KCP/smux-сессий. UDP и режим с одной сессией не меняются. Явное `proxy.bond: false` сохраняет прежнее поведение для несовместимого backend.

Сервер текущей VPS подтвердил поддержку этого режима реальными HTTPS-передачами, без обновления серверного бинарника или открытия портов. Новую версию следует испытывать как кандидат: совместимость чужого старого FreeTurn-сервера с TCP bond автоматически не определяется.

## Сравнение с iPhone

Изучен [anton48/vk-turn-proxy-ios, commit e94c6e2](https://github.com/anton48/vk-turn-proxy-ios/blob/e94c6e21be81ae9fd3614601874b69f244c71bc5/pkg/proxy/creds_vkcalls.go). Существенное различие — новый VK Calls API вместо используемой ранее цепочки `calls.getAnonymousToken`. В репозитории предусмотрены и CAPTCHA, и отдельная авторизация с cookie; отсутствие CAPTCHA не является безусловным обещанием сервиса.

Новая цепочка реализована в VPNN через его существующий HTTP-слой. Логин в личный VK-аккаунт, cookie администратора и Swift-компоненты для этого не понадобились.

В присланном историческом контексте iPhone использует WireGuard через UDP relay. Текущий VPNN использует TCP через TURN/DTLS/KCP/smux; это другой тракт. Возврат к WireGuard может быть следующим исследованием, но требует индивидуальных ключей, согласованного provisioning и отзыва на сервере. Подстановка общего legacy-профиля нарушила бы текущую модель индивидуального доступа, поэтому она не выполнялась. Старый IP из контекста не использовался вместо актуальной конфигурации.

## Фактические результаты

Все числа ниже относятся к текущему компьютеру и существующей VPS, не к Honor или МегаФону. Явный SOCKS не менял системные маршруты/прокси. В каждом варианте минимум три передачи; внешний IP отдельно проверялся через тот же SOCKS. Скорость включает установку соединения и HTTPS, измеряется в Мбит/с. Для сетевых сравнений исходный режим имел явное либо штатное на тот момент `bond: false`; новый режим — `bond: true`.

Анонимная живая авторизация прошла без вызова решателя CAPTCHA; выданы два TURN-адреса, подтверждённый пригодный срок — около 28 651 секунды. Это результат текущего испытания, а не гарантия неизменности VK API.

| --- | ---: | ---: | ---: |
| Прежний TCP, 1 сессия | 1 МиБ | 0,91 | 0,89–1,00 |
| Прежний TCP, 3 сессии | 1 МиБ | 1,08 | 1,01–1,41 |
| Прежний TCP, 6 сессий | 1 МиБ | 1,21 | 1,16–1,23 |
| Прежний TCP, 12 сессий | 1 МиБ | 1,12 | 1,07–1,27 |
| Повтор контроля, 6 сессий | 1 МиБ | 1,11 | 1,05–1,38 |
| TCP bond, 6 сессий | 1 МиБ | 4,12 | 2,50–4,22 |
| Повтор TCP bond | 1 МиБ | 4,74 | 4,35–4,98 |

| TCP bond, более крупная передача | 2 МиБ | 6,75 | 3,36–7,03 |

В сопоставимых повторах по 1 МиБ получен примерно четырёхкратный выигрыш. Результат по 2 МиБ приведён отдельно: его нельзя напрямую сравнивать с короткой передачей. В варианте с 12 сессиями во время начала замера были готовы 6, к концу — 12; увеличение числа само по себе не помогло. Оставлены 6 сессий, число allocations не повышено.

Отдельно одновременно испытаны две существующие подписанные идентичности устройств: медианы 3,96 и 4,30 Мбит/с, по три передачи 1 МиБ, оба egress подтверждены. Сумма медиан не объявляется измерением агрегатной скорости. Ёмкость восьми пользователей и ресурсы VPS требуют отдельных испытаний.

Память измерительного процесса вместе с локальным Xray в повторе TCP bond — около 61 МиБ RSS; CPU около 0,55 секунды за 11,5 секунды запуска. Это данные компьютера, а не VPS или батареи телефона. Изменение DNS-настроек в этой итерации не принималось: предыдущие эксперименты приведены в [отчёте 0.1.3](PERFORMANCE-0.1.3.md).

Сырые обезличенные результаты: `logs/vk-calls-live.txt`, `vk-calls-n1.json`, `vk-calls-n3-1m.json`, `vk-calls-n6-1m.json`, `vk-calls-n12-1m.json`, `vk-calls-control-repeat.json`, `vk-calls-bond.json`, `vk-calls-bond-repeat.json`, `vk-calls-default.json`, `vk-calls-bond-long.json`, `vk-group-a.json`, `vk-group-b.json`.

## Проверки и границы

Новые регрессионные проверки покрывают пять этапов авторизации, отрицательный анонимный user ID, единственную попытку нового пути перед legacy, терминальные ошибки, ограничение ответа, отсутствие секретов в ошибках, серверный срок реквизитов и включение/явное отключение TCP bond. Полный результат, Android-испытания и точные пропуски фиксируются в `logs/vk-calls-validation.json`.

Подписанный APK 0.1.4 проверен на API35-эмуляторе: свежий offline bootstrap и DNS прошли при запрете прямой VPS; затем VK подключился без решателя CAPTCHA. Перед независимым HTTPS экспортирован настоящий отчёт, подтвердивший режим VK, готовый захват и числовые счётчики. Прямой доступ к VPS был запрещён всем процессам, HTTPS вне TUN — независимому проверяющему процессу; приложению оставлен необходимый внешний доступ к VK. Получен ожидаемый egress `89.125.120.163`. Правила удалены, приложение и созданный эмулятор остановлены.

Пройдены 193 выбранных Flutter-теста, анализатор без замечаний, Go engine/Core и выбранные FreeTurn/VK/relay/KCP/mobile-тесты с vet, 12 deployment-тестов и 3 теста benchmark runner. Все три APK подписаны прежним сертификатом. Go race detector отдельно не запускался из-за отключённого CGO в текущем toolchain.

Новый клиент не создаёт второй TUN. Подпись конфигурации, контроль срока доступа, индивидуальный VLESS UUID и серверный отзыв остаются обязательными. Реальные Windows/Chrome IPv4/IPv6, Honor/МегаФон, сутки работы и расход батареи остаются незакрытыми испытаниями. Новый VK API может со временем изменить требования.

## Поставка и очистка



`tools/compact-workspace.ps1` по умолчанию составляет план; `-Apply` удаляет только проверенные каталоги из разрешённого списка. Каждый путь проверяется на принадлежность рабочему каталогу, reparse points, работающие исполняемые файлы и пересечение с файлами активного релиза/кандидатов. Gradle transforms пропускаются при работающей локальной Java, снимки AVD не удаляются при активном эмуляторе.

Удаляются загрузочные архивы и дублирующие chunks, старые тестовые APK/Windows-комплекты 0.1.1, промежуточный `client/build`, Flutter/Go-кэши и старый снимок тестового AVD. Ключи, private, исходники, установленные инструменты, модули зависимостей, актуальные кандидаты и recovery сохраняются. Упаковщик больше не зависит от лицензий внутри удаляемой тестовой сборки.

План и фактический результат: `logs/compact-workspace-plan.json`, `logs/compact-workspace-result.json`. После очистки повторная сборка заново создаст промежуточные кэши. Это не часть размера устанавливаемого приложения.
