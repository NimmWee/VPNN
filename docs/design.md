# Единый клиент Android и Windows — актуальный проект

Дата: 2 ноября 2026 года, Asia/Tomsk.
Статус: согласовано направление и исключение iPhone; реализация приложения ещё не начата, точная основа и техническая интеграция требуют проверки.

Этот файл заменяет трёхплатформенный вариант UNIFIED-APP-DESIGN-2026-11-02.md в части дальнейшей разработки. Историческое состояние серверов и испытания описаны в PROJECT-CONTEXT-2026-11-01.md; оно не является проверкой текущей VPS.

## Подтверждённый объём

- Одно приложение для Android и одно для Windows с общим интерфейсом и конфигурацией.
- Для пользователя не нужны отдельные Happ, Zanoza и VK-клиент на этих двух платформах.
- Три способа подключения в конечном объёме: прямые поддерживаемые протоколы KIT, VK TURN/FreeTurn и DNS-транспорт.
- Веб-админка: основная и резервные ссылки своих разрешённых звонков VK, серверы, приглашения устройств, отзыв доступа и публикация настроек.
- Приложение автоматически получает изменения конфигурации, когда есть доступный путь, и хранит рабочий кеш.
- Возможность развёртывания серверной части на чистой VPS одним запуском установщика с проверкой результата.
- Начальный круг пользователей — владелец и небольшая группа. Биллинг и публичная регистрация не нужны.
- Работать без субагентов.
- Уточнён порядок испытаний: **Windows проверяется непосредственно на компьютере, Android сначала через Android Emulator; физический Honor — позже**. Модель и версия Android телефона пока не установлены, это не блокирует подготовку эмулятора и Windows-сборки.
- **iPhone исключён из разработки.** Пользователь продолжает пользоваться существующим VK TURN Proxy на iPhone. Его приложение/профиль не менять в рамках разработки новых клиентов без отдельного запроса. Подпись Apple, TestFlight и джейлбрейк больше не являются зависимостями проекта.

## Известные адреса и границы текущего состояния

Со слов пользователя актуальный IP VPS — **89.125.120.163**. Домен — **chichy.space**, DNS управляются в REG.RU. Предложены записи A `ns` → `89.125.120.163` и NS `v` → `ns.chichy.space`; имя DNS-туннеля — `v.chichy.space`. Подтверждения публикации этих записей и работающего DNS-сервера нет.

Новый IP, доступ к SSH, ОС, службы, ресурсы, host key и серверная конфигурация заново не проверены. Нельзя автоматически применять прежние пароли, fingerprint, лимиты и результаты аудита старого IP 89.125.188.66 к этой машине.

Исторически iPhone/FreeTurn работал через МегаФон; это не испытание будущего Android/Windows-клиента. На прежнем сервере обнаруживались root-компрометация и автозапуск; новая серверная установка должна опираться на проверенные компоненты и свежие секреты, а не на безусловное восстановление полного снимка ОС.

## Предварительная архитектура

Первый кандидат основы — форк Karing (Flutter + модифицированный sing-box). До окончательного выбора проверить воспроизводимость сборок Android/Windows, лицензии конкретных зависимостей и интерфейсы встраивания транспортов. Наличие открытого репозитория не означает готовой совместимости.

```text
Общий интерфейс клиента
          ↓
Профиль устройства и диспетчер соединения
          ↓
Один виртуальный сетевой интерфейс
          ↓
Выбранный режим:
  прямой → совместимый протокол KIT → VPS → интернет
  VK → VK TURN → FreeTurn VPS → WireGuard → интернет
  DNS → доступный рекурсивный DNS → MasterDnsVPN VPS → TCP-интернет
```

Встраивать нужные библиотеки/модули в собственный клиент. Не заменять интеграцию запуском трёх внешних приложений. Во время работы одного режима не должно быть конкурирующих TUN-сессий.

Android: VPNService, исключение внешних транспортных сокетов из собственного VPN, проверка фона/батареи и переходов Wi-Fi/LTE. Windows: системный туннель, необходимые привилегии, корректный жизненный цикл фоновой части, восстановление маршрутов/DNS после отключения, сбоя и закрытия окна.

Смена режима — управляемое переподключение. Сохранение текущих TCP-сессий и бесшовное переключение не входят в первую версию. При полном отсутствии доступного внешнего пути приложение не сможет получить новую конфигурацию.

Начальный прямой профиль — VLESS/Reality. Hysteria2, VMess, Trojan, Shadowsocks, TUIC и прочие варианты добавляются по проверенной матрице. Все варианты XHTTP/AWG не обещать автоматически. MTProto не является общесистемным VPN.

DNS предназначен прежде всего для TCP: возможности произвольного UDP, звонков и игр требуют отдельного решения и проверки. Не путать туннелирование пользовательских данных через DNS с обычными настройками DNS/DoH.

## Пользовательский интерфейс первой версии

- Импорт приглашения по ссылке/QR/файлу.
- Выбор сервера и режима: «Обычный», «Через VK», «Через DNS».
- Одна кнопка подключения/отключения.
- Статус реального соединения, ошибка с понятным действием, трафик и время сеанса.
- Обновление настроек и обезличенная диагностика.
- Если VK потребует CAPTCHA — ручное прохождение внутри клиента; не обещать полное отсутствие CAPTCHA после централизованной смены ссылки.

Интерфейс не должен требовать ручного запуска локального SOCKS-сервера или ввода цепочек прокси. Такие связи — ответственность сетевой части приложения.

## Админка и индивидуальные доступы

Администратор управляет группами устройств, разрешёнными профилями и звонками. Устройства получают собственные токены/ключи; пароль root и учётные данные KIT API не выдаются клиентам. Отзыв одного устройства не должен требовать замены ключей всей группы.

Публикация версии конфигурации: проверка формата, подлинности и назначения для устройства, защищённая доставка, локальный кеш и резервные адреса. Ключи подписи/серверные административные секреты хранятся отдельно от публичного кода.

Обновление — перед подключением, при открытии и периодически во время работы. Можно показывать последнюю версию, получение которой подтвердило устройство. Офлайн-устройства не считаются мгновенно обновлёнными. Переход активной сессии на другой звонок может потребовать переподключения.

Ссылки звонков общие для назначенной группы, а ключи устройств — отдельные. Учитывать лимиты звонков/аллокаций, предусмотреть пул резервных ссылок. Смена конфигурации не снимает внешние ограничения VK или DNS-резолвера.

## Этапы и критерии результата

1. **Проверка основы и сборок.** Зафиксировать исходники, лицензии и инструментальную среду. Получить запускаемые базовые сборки Windows и Android. Проверить прямой тестовый профиль. Решение по основе принимать после этого.
2. **Объединение прямого режима и VK.** В одном клиенте, через один системный туннель, без отдельного VPN-приложения. Проверить выходной IP, реальные DNS/HTTPS, отключение, смену режима и восстановление маршрутов. Физический Android-тест обязателен перед заявлением о готовности.
3. **Централизованные настройки.** Админка, приглашения, отдельные доступы и смена ссылки звонка. Два клиента получают новую версию; проверены кеш, резервный адрес, недоступность админки и отзыв устройства.
4. **Встроенный DNS.** Совместимое клиентское ядро MasterDnsVPN, сервер и делегирование v.chichy.space. Проверить интернет без отдельной Zanoza/Happ на обеих платформах и на МегаФоне при недоступном прямом профиле.
5. **Установщик и восстановление.** Пустая VPS → необходимые службы/ключи/firewall → профили → проверки. Повторный запуск не дублирует правила. Зашифрованная копия и установочный комплект находятся вне основной VPS. Адреса в клиентах обновляются без пересборки приложения.
6. **Проверка устойчивости.** Длительная передача, сон/пробуждение и блокировка экрана, Wi-Fi/LTE, перезапуск служб/устройства, DNS/IPv6, память, скорость, энергопотребление, отсутствие циклов маршрутизации и восстановление после ошибок.

### Уточнение среды испытаний

Использовать официальный Android Emulator и AVD из Android SDK, при необходимости через Android Studio. Это виртуальное Android-устройство, а не расширение редактора само по себе. Эмулятор позволяет проверить APK, интерфейс, разрешение VPNService, сетевую логику, ошибки и переподключение.

На Windows-хосте проверены Windows 11 Pro x64, Intel i5-12400F, около 32 GiB RAM и 98 GiB свободного места на C: на момент проверки. Visual Studio 2022 Community обнаружен. Flutter, adb, emulator не найдены в PATH; Android SDK и Android Studio не найдены в стандартных проверенных каталогах. Это не полный поиск по всем дискам.

WMI сообщает HypervisorPresent=true; отдельные CPU-поля виртуализации при этом false. По этим данным нельзя объявлять виртуализацию выключенной в BIOS. Фактическую доступность ускорения проверить через `emulator -accel-check` после установки SDK. Windows-компоненты виртуализации, требующие перезагрузки, не переключались.

Для x86_64-эмулятора нужны совместимые native-библиотеки всех транспортов. Готовый ARM-only APK не считать автоматически пригодным для такого AVD; сборку ABI и VPN-путь проверить отдельно. Начать с одного AVD поддерживаемого API; при необходимости добавить второй для минимальной заявленной версии. Не обещать Android 7 без проверки основы и зависимостей.

Успех в эмуляторе не подтверждает работу белых списков МегаФона, поведение оболочки Honor, расход батареи или ARM-сборки. Эмулятор использует сеть компьютера: активный сторонний VPN на Windows и доступность внешних узлов надо фиксировать в результатах. Физический телефонный прогон остаётся этапом перед заявлением о готовности мобильного клиента, но проводится позже по решению пользователя.

Для активных испытаний использовать выделенных тестовых клиентов; не запускать стенд с ключом работающего iPhone, чтобы не переключить его WireGuard endpoint.

## Установщик и размещение

Сервис настроек и резервные копии должны переживать потерю VPN-ноды. Конкретное размещение, домен админки, формат конфигурации и инструмент развёртывания пока не выбраны.

Один запуск установщика не означает автоматическую покупку VPS, доступ к DNS-провайдеру или отсутствие пользовательского разрешения Android VPN/Windows UAC. Автоматизация внешних услуг зависит от API и выданных полномочий.

Не требуется переустанавливать текущую VPS или выключать рабочий iPhone ради разработки клиента. Изменения серверов и платные услуги выполняются только в рамках отдельного текущего поручения.
