# Проверка DNS и VK

## Что уже подтверждено

2 ноября 2026 года на VPS 89.125.120.163 установлены отдельные `vpnn-dns`, `vpnn-vk`, `vpnn-egress`. Они включены в автозапуск. Исходные KIT/Xray, nginx, fail2ban и `vps-vk` для iPhone продолжают работать.

- **DNS:** MasterDnsVPN AES-256-GCM на UDP/53, зона `v.chichy.space`. A/NS в REG.RU опубликованы. HTTPS через публичные рекурсивные DNS 1.1.1.1 / 8.8.8.8 подтвердил выход 89.125.120.163. Исправлены авторитетные NS/SOA зоны; ответы проверены через оба рекурсора.
- **VK:** FreeTurn на UDP/56010 → отдельный VLESS только на loopback VPS. Реальный тест своего звонка после ручной CAPTCHA передал HTTPS с выходом 89.125.120.163. Это проверка встроенного транспортного движка на Windows, без системного VPN на компьютере.
- **Android:** новый клиент установлен в Android 15 x86_64 Emulator. Получение подписанных профилей и DNS VPN работают. Отдельный HTTPS-процесс прошёл проверку при запрете прямых подключений к VPS **и HTTPS через внешний интерфейс вне tun0**. Тестовые firewall-правила в эмуляторе удалены в `finally`.
- **Android VK:** проверка открылась во встроенном WebView приложения. После неё VK установил соединение, HTTPS прошёл при запрете прямого VPS и HTTPS вне tun0. Ручное задание в этом сеансе не появилось; автоматический решатель CAPTCHA не включался. Проброс страницы в браузер компьютера не используется.
- Переключение работающего VK → DNS и HTTPS после переключения также проверены. Ручное обновление неизменённых настроек не переписало профили и не прервало проверяемый путь VK.
- При действующем проверенном кеше начальное подключение больше не ждёт выдачу конфигурации. Проверено холодным запуском при DROP пакетов к локальному API: до подключения обращений к API не было, DNS передал HTTPS. Все временные правила удалены. Подтверждённый отзыв доступа очищает кеш в памяти.

## Windows: следующий ручной тест

1. Актуальная папка запуска: `C:\VPNN\artifacts\windows-transport-test-v2`. Запускайте **VPNN.exe** вместе со всеми файлами папки. Это обычная тестовая сборка, способная менять прокси/маршруты при подключении. Агент её не запускал. Предыдущая папка сохранена отдельно.
2. Для чистого сравнения отключите другое VPN-приложение. Примите начальное заявление основы, если оно появится.
3. На главной странице вставьте приглашение из `C:\VPNN\private\transport-test\windows-invitation.txt` и добавьте устройство. Приглашение — секрет доступа; не отправляйте его посторонним.
4. Выберите **Через DNS**, подключитесь, нажмите проверку интернета. Затем проверьте обычный браузер. Для проверки МегаФона можно подключить компьютер к раздаче телефона и повторить с выключенным другим VPN.
5. Затем переключитесь на **Через VK**. Если потребуется CAPTCHA, откройте страницу проверки и пройдите её вручную. На Android она открывается внутри приложения; после страницы успеха вернитесь кнопкой «Назад». Смена режима переподключает туннель; текущие загрузки могут прерваться.
6. Запишите для каждого режима: сеть, прошла ли проверка, открываются ли сайты, скорость. Реальную фильтрацию МегаФона эмулятор полностью не воспроизводит.

`C:\VPNN\Start-VPNN.cmd` остаётся запуском **SAFE_MODE** из рабочего каталога сборки; он не подходит для сетевого теста. Используйте обычный пакет из пункта 1.

## Настройки на этом этапе

Временный сервис выдачи настроек работает только на этом компьютере: `127.0.0.1:8098`. Для Windows его адрес в приглашении — localhost; для эмулятора — `10.0.2.2`. Это не серверная админка в интернете. После перезапуска ПК сервис можно запустить `C:\VPNN\Start-Test-Control.cmd`. Если он уже работает, повторно запускать не нужно.

Кеш клиента хранит проверенные настройки семь дней; при недоступной локальной службе новые настройки не поступят. Действующий кеш позволяет запустить туннель до очередного получения настроек. Проверка сервера продолжается периодически и по кнопке; уже подтверждённый отзыв не разрешает подключение. Неизменённый профиль сохраняется до момента, когда его сроку остаётся менее суток; при сокращении доступа или изменении содержимого файл заменяется сразу. Приглашения и серверные параметры тестового владельца лежат в `C:\VPNN\private` с доступом текущего пользователя Windows и SYSTEM. На VPS исходные параметры — `/etc/vpnn-transports/owner.json`, root-only. Пароль SSH в файлы не записывался.

Тестовые устройства используют одну пару внутренних сетевых ключей владельца. Отдельные токены выдачи настроек и Client ID уже есть, но полный индивидуальный сетевой отзыв/автоматическая синхронизация сервера ещё не закончены. Этот комплект предназначен для испытаний владельца, а не раздачи группе.

## Ограничения

- DNS передаёт прежде всего TCP. Произвольный UDP, игры, QUIC и голос не подтверждены. Скорость DNS может существенно уступать VK.
- Домен помогает сохранить имя при смене VPS. DNS-туннель позволяет обойти необходимость прямого доступа клиента к IP только пока доступный рекурсор действительно передаёт запросы к зоне. Оператор может фильтровать и этот путь.
- Windows системные маршруты проверяет пользователь. На хосте агент запускал только SAFE_MODE; отдельные транспортные проверки использовали явный локальный прокси.
- APK `vpnn-android-x64-transport-test.apk` — для эмулятора x86_64. Для телефона собраны `VPNN-Android-arm64-test.apk` и `VPNN-Android-armv7-test.apk`, заявленный минимум Android 7.0/API24 подтверждён метаданными APK. На физическом Honor они ещё не запускались. Первое получение настроек на телефоне пока требует доступного сервиса конфигурации; адрес эмулятора `10.0.2.2` для телефона не подходит. Публичный HTTPS-сервис и независимый от него первоначальный импорт — следующий этап.
- Установщик восстановления, серверная админка HTTPS и демон постоянного участника звонка в этом этапе не делались.

## Обслуживание VPS

Статус: `systemctl status vpnn-dns vpnn-vk vpnn-egress`.
Остановить только новый комплект: `systemctl stop vpnn-dns vpnn-vk vpnn-egress`.
Журнал DNS: `journalctl -u vpnn-dns -n 50 --no-pager`.
DNS слушает конкретный внешний IPv4, поэтому `systemd-resolved` на loopback оставлен на месте. В firewall добавлены только 53/udp и 56010/udp. VLESS и SOCKS egress наружу не слушают. После проверки новые три службы занимали суммарно около 37 МиБ памяти, рестартов по ошибкам не было.
