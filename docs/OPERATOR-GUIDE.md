# Инструкция владельца VPNN

Для локальной приёмки используйте [кандидат 0.1.6+7](../artifacts/p2-local/MANIFEST.json). [Комплект 0.1.2+3](../artifacts/LATEST.json) сохранён для возврата.

## Windows

1. Для первого системного испытания выбери отдельный момент, когда можно отключить другой VPN. VPNN и другой владелец системных маршрутов могут мешать друг другу. Агент это испытание на рабочем ПК не запускал.
2. Полностью выйди из предыдущей версии через меню трея: закрытие окна может только скрыть его. Распакуй весь `VPNN-User-Windows-x64-0.1.6.zip` и запусти `VPNN.exe` из распакованной папки. `Start-VPNN-Release.cmd` запускает комплект 0.1.2+3 для возврата.
3. Нажми «Импортировать файл подключения» и выбери C:\VPNN\private\transport-test\windows-production-bootstrap.json. Это заменяет старый localhost-адрес в приглашении на публичную панель. Импорт работает без предварительного обращения к VPS, пока подписанный файл действителен.
4. Выбери «Через DNS», подключись, разреши запрос прав администратора для системного TUN, дождись готовности транспорта и HTTPS-проверки. Затем отдельно проверь «Через VK». Для VK иногда нужна ручная CAPTCHA.
5. Выбери «Автоматически», чтобы проверить переключение между назначенными маршрутами. Экран покажет фактический маршрут. Если все пути недоступны, приложение останавливает туннель и показывает ошибку.

Start-VPNN.cmd запускает прежний SAFE_MODE и не является рабочим VPN. Публичные ZIP не содержат доступа; нужен индивидуальный файл/приглашение от администратора.

## Android

Новый applicationId: space.chichy.vpnn, минимум Android 7. APK подписаны одним собственным release-ключом. Для большинства современных Honor нужен arm64; для старого 32-битного устройства — armv7. x86_64 предназначен для эмулятора. Точную архитектуру Honor ещё нужно проверить.

Установи соответствующий APK, прими заявление, импортируй индивидуальный файл подключения, разреши Android VPN и уведомления. У каждого физического устройства должен быть свой доступ: не раздавай всем один файл тестового эмулятора. На Honor отдельно проверь ограничения батареи/фоновой работы.

В эмуляторе подтверждены DNS, offline bootstrap при запрете VPS, автоматический VK → DNS, работа в фоне и восстановление после остановки процесса. Эти проверки не заменяют испытания реального телефона и МегаФона.

## Администратор

Открой https://vpn.chichy.space. Ключ входа лежит в C:\VPNN\private\control\admin.secret; это отдельный ключ, не пароль SSH. Никому из пользователей его не передавай.

- В группе вставь разрешённые ссылки своих VK-звонков, по одной на строку. Нажми «Опубликовать настройки». Менять их отдельно на каждом устройстве не требуется.
- Сверяй опубликованную и применённую сервером версии. После изменения подожди до десяти секунд и нажми «Обновить». Устройства с доступом к панели запрашивают настройки примерно раз в две минуты, а также вручную. Действующая сессия при изменении профиля может переподключиться.
- Для нового устройства выбери группу, создай приглашение, сразу скопируй его и скачай «Файл первого подключения». Файл содержит токен, ключи конкретного устройства и подписанные настройки; передавай его по доверенному каналу и храни как пароль. Подпись не делает файл из неизвестного источника доверенным.
- Приглашение показывается один раз: сервер хранит хэш токена и не восстанавливает его из списка устройств. Сохрани свой экземпляр. Подписанный файл имеет срок действия, показанный в приложении; при истечении нужен свежий файл либо актуальные настройки через панель.
- «Отозвать доступ» закрывает индивидуальные DNS/VK-ключи после применения reconciler. При изменении состава устройств собственные relay/egress могут переподключить другие сессии. Обычные профили из 3X-UI требуют отдельного механизма отзыва.
- Текущий лимит — восемь активных устройств. Отозванные устройства слот не занимают.

JSON сетевых профилей пока предназначен для технического администратора. Не меняй рабочие ключи/подстановки ради изменения одной ссылки звонка. Автоматический вход в VK-аккаунт и создание звонков пока не реализованы.

## Когда IP не отвечает из РФ

Обычное имя домена указывает на тот же IP и само по себе блокировку не обходит. Встроенный DNS-туннель передаёт данные через рекурсивный резолвер в делегированную зону, а VK — через внешний TURN-путь. Оба способа зависят от доступности соответствующего внешнего маршрута. DNS поддерживает TCP; игры/QUIC и другие UDP-приложения не являются подтверждённым сценарием.

Записи REG.RU: A ns → 89.125.120.163; NS v → ns.chichy.space; A vpn → 89.125.120.163. DNS-серверы всего домена остаются REG.RU. При смене единственной VPS/IP нужно обновить обе A-записи, оставить делегацию v и проверить распространение DNS. Дополнительная собственная VPS не нужна.

## Резервная копия

Архив: C:\VPNN\artifacts\VPNN-Recovery-Backup.enc. Ключ отдельно: C:\VPNN\private\recovery\recovery.key. Архив включает исходную подпись настроек, доступы устройств, административный ключ, TLS и Android signing. Потеря ключа делает архив непригодным. Потеря Android signing без backup мешает обновлять установленный APK прежней подписью.

Восстановление описано в C:\VPNN\deploy\README.md. Комплект подготовлен и dry-run проверен; реальный apply на чистой ОС ещё не испытан. Не переустанавливай действующую VPS исключительно ради проверки этого сценария.

## Исправления 0.1.2

На Windows управляемое подключение теперь включает TUN с перехватом IPv4/IPv6, а ядро сообщает фактическую готовность TUN. Ошибка захвата или отказ прав останавливают подключение и показывают причину. Успех внутреннего DNS/VK транспорта сам по себе не объявляется успешным системным VPN.

Действующие TURN-реквизиты VK сохраняются в ограниченном кэше памяти процесса при переключении режимов. Срок остался прежним: около девяти минут с учётом запаса. При истечении, отказе VK, неподтверждённом освобождении старой allocation или перезапуске приложения авторизация может потребоваться снова. Файлы с такими временными секретами не создаются. Если CAPTCHA не была успешно пройдена и реквизиты не получены, сохранять для повторного подключения пока нечего.
