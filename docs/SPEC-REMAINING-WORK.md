# VPNN — спецификация оставшихся работ и исследования скорости

Версия документа: 1.0. Дата: 3 ноября 2026 года, Asia/Tomsk.

Базовая версия клиента: **0.1.2+3, кандидат для испытаний**. Документ описывает предстоящую работу; пункты ниже не считаются реализованными или проверенными только потому, что внесены в спецификацию. Детальные планы изменений составляются отдельно для каждого блока после получения необходимых измерений.

## 1. Цель и границы

Довести VPNN до повседневного использования владельцем и небольшой группой: одно приложение Android/Windows, выбор обычного подключения, VK и DNS, централизованные настройки, понятные ошибки, устойчивое восстановление и повторяемое развёртывание.

Обязательные ограничения:

- Проект расположен в `C:\VPNN`. Работать без субагентов.
- Используется одна VPS: `89.125.120.163`, Ubuntu amd64, около 1 ГБ RAM. Дополнительные собственные VPS не планируются.
- Домен `chichy.space`, панель `https://vpn.chichy.space`, DNS-зона `v.chichy.space`. Простая замена IP доменом не создаёт DNS-туннель и сама по себе не устраняет блокировку IP.
- iPhone-клиент исключён из разработки. Существующий отдельный iPhone-контур на VPS сохраняется как внешний legacy-компонент.
- Агент не включает системный VPN на рабочем Windows, не меняет его маршруты/прокси и не закрывает пользовательские VPN-процессы. Пользователь сам запускает такой тест. Для автоматических испытаний допустимы изолированный Android-эмулятор и явный локальный SOCKS без изменения системной сети Windows.
- Секреты, ссылки-приглашения, cookie, ключи устройств и пароли не включаются в исходники, публичные архивы, диагностические отчёты и этот документ. CAPTCHA проходит пользователь вручную.

## 4. P0 — подтвердить работу подключений

### NET-01. Windows: настоящий выход через VPN

- Полностью выйти из старого экземпляра через трей, запустить полный комплект 0.1.2, разрешить запрос администратора и проверить DNS, затем VK после успешной ручной авторизации.
- Проверить внешний IPv4 свежим запросом из Chrome и независимого процесса ОС. Для текущей VPS ожидаемый IPv4 — `89.125.120.163`.
- Проверить IPv6 отдельно: при наличии IPv6 он должен проходить предусмотренным путём либо явно блокироваться выбранной политикой, без выхода с домашнего IPv6.
- Проверить отключение: приложение убирает свои маршруты/прокси; чужие настройки не повреждаются.

**Приёмка:** фактический IP подтверждён вне внутреннего Core-probe; состояние интерфейса соответствует результату. Отказ UAC, сбой TUN, недоступность транспорта и отмена не оставляют ложный статус успешного подключения.

### VK-01. Переключения и повторная CAPTCHA

- После одного успешного VK-подключения выполнить минимум пять циклов VK → DNS → VK в пределах срока действующих реквизитов.
- Отдельно проверить истечение срока, перезапуск Core, смену звонка и отклонение реквизитов сервером.
- Различать повторную авторизацию из-за потери локального состояния и законный новый запрос VK. Не продлевать срок реквизитов искусственно.

**Приёмка:** реконструкция провайдера сама по себе не создаёт новый запрос авторизации при пригодном кэше. При инвалидировании выполняется штатная авторизация. Незавершённая CAPTCHA не считается успешным входом. Кэш не разделяется между разными устройствами/звонками и не создаёт файлов с временными TURN-секретами.

### AND-01. Реальный Honor/Android

- Уточнить модель, точный Android и ABI; установить подходящий подписанный APK.
- Проверить домашний Wi-Fi, МегаФон LTE, переходы между ними, экран выключен и возврат приложения на передний план.
- Провести отдельные испытания при обычном интернете и при реально действующих ограничениях оператора. Зафиксировать доступность каждого пути.

**Приёмка:** внешний IP, TCP-трафик и переключения подтверждены на устройстве; записаны ограничения фоновой работы и расход батареи. Заявленный minSdk24 и эмулятор не заменяют проверку Android 7 на реальном устройстве.

## 5. P1 — устойчивость и достоверная диагностика

| ID | Требование | Приёмка |
| --- | --- | --- |
| REL-01 | Сон/пробуждение Windows, пропажа сети, смена Wi-Fi/LTE, остановка процесса и перезапуск Core | После восстановления сети есть рабочая сессия либо понятная ограниченная ошибка; нет второго TUN и бесконечной цепочки запусков |
| REL-02 | Проверить отмену, отказ прав, CAPTCHA, исчерпание резервов, удалённый отзыв и недоступную панель | Отказ/отзыв не обходятся переключением протокола; отменённая операция не включает VPN позднее |
| REL-03 | Длительный прогон: сначала несколько часов на одном устройстве, затем не менее суток | Зафиксированы обрывы, повторы авторизации, CPU/RAM и батарея; нет устойчивого роста памяти/дескрипторов |
| DIA-01 | Разделить состояния «получаем настройки», «создаём системный туннель», «готов транспорт», «проверяем выход», «требуется CAPTCHA» | Пользователь видит этап и причину отказа, а не один бесконечный индикатор |
| DIA-02 | Продумать независимую проверку системного выхода и отображение актуального IP | Внутренняя проверка Core не выдаётся за доказательство перехвата Chrome/ОС; ответы старого маршрута отбрасываются |
| DIA-03 | Экспорт краткого диагностического отчёта | Версия/режим/этап/тайминги/счётчики доступны без токенов, ключей, cookie и полных ссылок звонка; чувствительные поля удаляются до экспорта |

Для DIA-02 предусмотреть подписанные ожидаемые выходные адреса узла: адрес relay не всегда обязан совпадать с публичным egress после NAT или при IPv6. Изменение схемы конфигурации должно учитывать совместимость и миграцию.

Политику при потере VPN нужно определить явно: восстановление обычного интернета либо блокировка трафика до восстановления туннеля. Наличие текущего fail-closed на ошибке конфигурации не означает готового системного kill switch.

## 6. P1 — исследование и увеличение скорости

### 6.1. Цель и исходная неопределённость

Повысить полезную скорость и отзывчивость доступных путей на одном VPS, сохранив обход ограничений, проверку маршрута, шифрование и стабильность. Фиксированный результат в Мбит/с до измерений не обещается. Для DNS приоритетом может оказаться отзывчивость страниц и сообщений, для VK — длительная передача и загрузки.

Ранние цифры из переписки: старый VK-клиент давал примерно 5/5 Мбит/с, после разгрузки назывались 10 download / 6 upload. Для обычного интернета назывались 13 и 23 Мбит/с и ping 36 мс; направления и условия требуется уточнить. Это другой клиент/период, а не базовый замер VPNN 0.1.2.

### SPD-01. Сначала воспроизводимый замер

Записывать для каждого результата:

- Клиент/версию/ABI/ОС, сеть, время, режим ограничений, профиль и количество активных пользователей.
- Подтверждённый внешний IP и признак реального пути через туннель.
- Download/upload в **Мбит/с**, время до первого байта, время подключения, RTT p50/p95, обрывы и переподключения.
- Одну передачу и несколько параллельных передач: результаты хранить отдельно.
- CPU/RAM VPS и клиента, загрузку отдельных процессов/ядер; для Android — батарею и нагрев в сопоставимом интервале.
- Для транспорта — доступные счётчики повторов, очередей, потерь, полезных байтов и накладного трафика. Полные DNS QNAME туннеля и секреты авторизации в отчёт не писать.

Для каждой конфигурации провести не менее трёх коротких повторов с одинаковым объёмом/длительностью, затем отдельный длительный тест лучшего варианта. Сравнивать медиану и разброс, сохранять сырые обезличенные результаты. Нагрузку и объём заранее ограничить; не превращать проверку в бесконечный генератор трафика.

Измерять отдельно участок клиент → тот же VPS и полноценный HTTPS через VPS к согласованному доступному ресурсу. Временный измерительный endpoint при необходимости размещается **на существующей VPS**, с ограничениями доступа, объёма и срока жизни. Новый собственный сервер не требуется.

**Приёмка:** есть таблица исходных результатов, повторяемая методика и доказательство пути. Если прямой канал недоступен, ставить «N/A», а не использовать ноль для расчёта относительного прироста. Эмулятор подходит для функциональной проверки и поиска регрессий; его скорость не переносится на Honor/МегаФон.

### SPD-02. Матрица условий

| Условие | Что сравнить | Назначение |
| --- | --- | --- |
| Домашняя сеть, обычный интернет | Без VPN, обычный профиль, VK, DNS — где доступны | Отделить ограничения клиента/VPS от мобильного оператора |
| МегаФон, обычный интернет | Те же доступные варианты, один телефон и место | Оценить накладные расходы в сопоставимых условиях |
| МегаФон, ограничения активны | Реально доступные VK/DNS; прямой путь может быть N/A | Оценить именно работоспособность обхода и его полезную скорость |
| Эмулятор с запретом прямой VPS и внешнего HTTPS вне TUN | DNS, резерв, отсутствие обхода через DIRECT | Подтвердить маршрут; не считать эталоном производительности телефона |
| Один, затем два/четыре и при необходимости до восьми клиентов | Агрегатная и индивидуальная скорость, задержка, память | Найти безопасную ёмкость VPS; текущие восемь слотов не являются обещанием одинаковой скорости |

### SPD-03. Гипотезы и эксперименты

Это кандидаты для исследования, а не готовые настройки. Перед экспериментом проверить реальные параметры, допустимые диапазоны и поддержку обеими сторонами в текущих исходниках. Менять одну группу параметров за раз, сохранять рабочую конфигурацию для отката.

| Направление | Что проверить | Условие полезности |
| --- | --- | --- |
| Обычный профиль | Доступность IP, выбранный протокол/транспорт, путь до VPS, CPU/шифрование, внешнюю полосу и размер передачи | Найден реальный предел, а не ошибка захвата/выбора маршрута |
| VK: параллелизм | Сравнить 1/3/6/12 TURN-потоков в рамках текущего ограничения engine; смотреть нагрузку и конкуренцию клиентов | Дополнительные потоки дают повторяемую пользу без роста обрывов/лишней авторизации и перегрузки VPS |
| VK: распределение нагрузки | Проверить по коду, может ли один TCP-поток использовать несколько каналов, нет ли очереди/блокировки за медленным потоком; оценить существующий совместимый bonding | Ускоряется полезная передача, а не только число соединений; wire-совместимость сохранена |
| VK: relay/путь | Измерить RTT и качество доступных разрешённых TURN-адресов; оценить выбор среди уже выдаваемых сервисом адресов | Улучшаются задержка/скорость без дополнительной собственной VPS и неконтролируемых allocations |
| DNS: резолверы | Сопоставить доступные резолверы оператора и допустимые внешние: RTT, пропускную способность, потери, ограничения запросов и делегацию | Выбран действительно работающий рекурсивный путь; больше резолверов не означает автоматически быстрее |
| DNS: нагрузка/фрагментация | Изучить размеры полезной DNS-нагрузки, EDNS/усечение, сегментацию, повторы и совместимость ответов | Меньше повторов и задержек при сохранении прохождения через реальные резолверы |
| DNS: окна/очереди | Проверить доступные лимиты параллельных запросов, окна передачи, polling/ожидание, буферы и обработчики | Выше goodput без переполнения очередей, роста RAM и деградации при нескольких клиентах |
| TUN и локальный путь | Сопоставить несколько допустимых MTU, стоимость копирования/буферизации и настройки стека | Измеримое улучшение на том же устройстве. MTU TUN и размер DNS-пакета рассматриваются отдельно |
| VPS 1 ГБ | Профилировать CPU и память конкретных процессов; проверить журналы, лимиты, буферы, GC и фоновые задачи | Изменение устраняет подтверждённое узкое место. Не выключать защиту или службы без установленной причины |
| Внешний TCP-участок | Если он ограничивает передачу, отдельно оценить TCP-настройки, включая допустимый congestion control | Эффект подтверждён на нужном участке; настройка TCP не объявляется прямым ускорителем внешнего UDP/TURN/DNS |
| Автоматический выбор | После замеров рассмотреть профили «скорость / устойчивость / экономия батареи» и выбор доступного пути | Решения используют актуальные измерения, не создают второй TUN и не переключают протокол посреди пользовательской операции без понятной политики |

Сжатие исследовать только для данных, где оно может дать пользу: многие HTTPS-передачи уже содержат сжатый или плохо сжимаемый поток. Не добавлять CPU-расход и задержку без замера.

### SPD-04. Критерии принятия оптимизации

- Прирост повторяется и превышает обычный разброс базовых замеров; улучшение одной удачной попытки недостаточно.
- Нет ухода трафика напрямую, потери IPv6-политики, обхода подписи/отзыва или ослабления шифрования.
- Нет неприемлемого роста p95 задержки, обрывов, CAPTCHA, памяти и расхода батареи. Допустимые компромиссы явно отражаются в профиле.
- Проверены одно устройство и небольшая одновременная группа; параметры ограничены администратором ресурсами VPS.
- Есть способ вернуть прежние значения и краткий отчёт «условия → изменение → результат → решение».

Выход блока скорости: базовая таблица, список подтверждённых узких мест, результаты экспериментов, выбранные настройки по режимам и честные пределы. Численные целевые скорости утверждать после SPD-01, отдельно для обычного пути, VK и DNS.

| ADM-02 | Выдача, отключение и отзыв обычных доступов через существующий 3X-UI на том же VPS | Тестовый доступ работает до отзыва и прекращает работать после; секрет API остаётся на сервере, существующие пользователи KIT не повреждаются |
| ADM-03 | Удобные группы, ссылки VK, назначения устройств, лимиты и состояние применения | Администратор видит опубликованную/применённую/полученную устройством версии и понимает, где обновление задержалось |
| ADM-04 | Доставка нового звонка при недоступном прямом API | Пригодный кэш позволяет начать доступным путём и обновиться через него; просроченный файл получает понятную инструкцию, подпись/срок не отключаются |

Текущий индивидуальный DNS/VK-отзыв сохранить. Не заменять его простым скрытием устройства в интерфейсе. Старые персональные приглашения не превращать в общий ключ для всей группы.

## 8. P2 — VK-аккаунт и жизнь звонков

### VK-02. Автоматизация администратора

- Исследовать разрешённый вход собственного VK-аккаунта, создание/обновление своих звонков и публикацию ссылки группе.
- Продумать защищённое хранение сессии, ручные проверки, окончание сессии, выход/отзыв и отсутствие доступа пользователей к cookie администратора.
- Проверить отказ VK и недоступную ссылку: ограниченные повторы, понятное состояние, резервный DNS при его доступности.

**Приёмка:** владелец прошёл необходимую авторизацию, ссылка обновляется у назначенных устройств, отказ не вызывает бесконечного создания звонков. CAPTCHA остаётся ручной.

### VK-03. Нужен ли постоянный участник

Сначала установить, нужен ли вообще постоянно подключённый участник для требуемой выдачи/обновления TURN. Только после этого оценивать лёгкий поддерживающий процесс на той же VPS, его RAM/CPU, восстановление и соблюдение требований сервиса. Постоянный тяжёлый браузер на 1 ГБ RAM не принимать решением по умолчанию. «Вечный звонок» не обещать: измерить реальный срок жизни и сценарий замены.

## 9. P1 — резервные копии и восстановление

| ID | Требование | Приёмка |
| --- | --- | --- |
| OPS-01 | Определить полный состав восстанавливаемой системы | Явно перечислены VPNN control/DNS/VK, устройства/подпись, TLS, Android signing и область 3X-UI/legacy. Текущий ограниченный restore не называется восстановлением всей VPS |
| OPS-02 | Испытать сценарий на чистой ОС при плановом переносе/переустановлении | После подготовки домена и файлов одна документированная команда поднимает заявленный стек; проверены прежние устройства, подписи, отзыв и HTTPS; записаны время восстановления и оставшиеся ручные действия |
| OPS-03 | Проверить повторный запуск и прерванное восстановление | Не теряются ключи/новые данные; чужой работающий стек не перезаписывается; ошибки указывают этап |

Не стирать рабочую VPS ради проверки документа. Смена IP требует обновления A-записей `ns` и `vpn`; NS-делегация `v` сохраняется. Предусмотреть проверку DNS, повторное получение TLS, актуальные ожидаемые egress-адреса и проверку нового SSH host key через доверенный канал.

## 10. P2 — установка и обновления

- **DIST-01:** Windows installer, который устанавливает полный комплект, корректно работает с правами/Helper и существующим экземпляром, сохраняет доступы и имеет понятное удаление.
- **DIST-02:** собственный канал подписанных обновлений с проверкой целостности/версии, поэтапной установкой и откатом. Чужой updater FlClash не включать.
- **DIST-03:** APK тем же Android-ключом для нужных ABI; стабильные версии/инструкции, SHA-256 и соответствующие исходники/уведомления лицензий.

**Приёмка:** обновление тестового устройства не теряет настройки и идентичность, неподходящий/подменённый пакет отклоняется, неудачное обновление оставляет работоспособный путь восстановления.

## 12. Итоговая готовность и открытые решения

Для повседневного использования должны быть закрыты NET-01, VK-01, AND-01, основные REL/DIA-сценарии, известны измеренные пределы скорости и проверена процедура восстановления заявленного стека. Готовность подписанных обновлений, автоматического VK-аккаунта и обычных 3X-UI-профилей отмечается отдельно; один общий статус «всё готово» их не подменяет.

До реализации соответствующих блоков уточнить:

1. Точную модель/Android/ABI Honor и результат повторного Windows-теста 0.1.2.
2. Приоритет скорости: страницы/мессенджеры, большие загрузки, видео либо несколько пользователей одновременно.
3. Политику при потере VPN и необходимость UDP/QUIC/игр: DNS-путь сейчас заявлен для TCP, это отдельное ограничение функциональности.
4. Какой состав старого KIT/3X-UI/iPhone-контура обязан входить в обещание восстановления одной командой.
5. Допустимые компромиссы скорости, задержки и батареи после базовых замеров.

Этот документ не запускает испытания, не разрешает переустановку текущего сервера и не возобновляет удалённую автоматизацию `vk-turn`. Его назначение — зафиксировать оставшийся объём и критерии результата для последующей работы.
