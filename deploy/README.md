# Развёртывание и восстановление VPNN

Публичный адрес https://vpn.chichy.space. Административный ключ хранится отдельно от SSH в C:\VPNN\private\control\admin.secret.

## Действующая VPS

Control: vpnn-control.service, пользователь vpnncontrol, HTTP только127.0.0.1:8098. Состояние /var/lib/vpnn-control/state.json, ключ подписи state.json.signing. Nginx KIT маршрутизирует SNI на loopback10448. Certbot продлевает сертификат автоматически.

Сетевой узел: vpnn-node-sync.service читает атомарное control-состояние на той же VPS. Индивидуальные backend-службы vpnn-dns@d-хэш слушают loopback54001+, публичный DNS gateway UDP53 направляет запросы только действующим устройствам. FreeTurn UDP56010 ведёт в loopback VLESS24430/SOCKS24431. Ключи лежат в /etc/vpnn-node и /etc/vpnn-transports. Старые KIT/x-ui и отдельный iPhone vps-vk сохранены.

## Обновление на существующей VPS

Control-stage содержит install.py, vpnn-control и sha256.json; при самом первом переносе отдельно нужны state.json, state.json.signing, admin.secret. Установщик сохраняет существующие данные/ключи, проверяет checksum/nginx и делает резервные копии меняемых файлов.

```sh
sudo python3 install.py --domain vpn.chichy.space --stage /root/vpnn-control-stage
```

Это обновление control на текущем KIT-узле. Оно не переустанавливает DNS/VK и не является восстановлением чистой ОС. install_node.py — отдельная первоначальная миграция на индивидуальные сетевые доступы; на текущей VPS она уже выполнена.

После обновления KIT проверь include /etc/nginx/vpnn-stream-map.conf внутри $kit_upstream: KIT может перегенерировать свой stream-файл. Повторный запуск control installer восстанавливает include. Не копируй поверх работающего KIT конфигурацию nginx из сценария чистого восстановления.

## Снимок и комплект восстановления

- VPNN-Recovery-Backup.enc — AES-256-GCM снимок control/transport/node конфигураций, исходного ключа подписи, TLS и Android signing.
- private/recovery/recovery.key — отдельный ключ расшифровки, не входит ни в один публичный архив.
- VPNN-Recovery-Tools-0.1.1.tar.gz — закреплённые Linux amd64 control/gateway/FreeTurn/MasterDNS/Xray, reconciler, сценарии и SHA-256; секретов нет.
- VPNN-Sources-0.1.1.zip — соответствующие исходники, лицензии, инструкции сборки.

Подмена снимка, неверный ключ, выход путей из staging, ссылки, дубликаты и превышение размера отклоняются. Снимок обновлён после индивидуальной миграции. Сохрани backup и ключ в отдельных надёжных местах.

## Проверка без применения

Распакуй tools в отдельную папку, положи рядом зашифрованный backup и передай ключ отдельным защищённым файлом. Dry-run не меняет системные файлы и не запускает службы:

```sh
python3 restore_stack.py --backup VPNN-Recovery-Backup.enc --key-file recovery.key --address 89.125.120.163
```

Нужен python3-cryptography. В Windows dry-run также проверен. На действующей Ubuntu проверены безопасное staging/план и отказ assert_clean поверх существующего VPNN/KIT. Проверка не означает, что чистый apply уже испытан.

## Одна команда на чистой Ubuntu amd64

Сначала восстанови/обнови DNS A ns и vpn на адрес единственной VPS. NS v → ns.chichy.space и основной DNS REG.RU остаются. Подготовь консоль провайдера, backup, отдельный ключ и распакованный tools.

```sh
sudo bash restore.sh --backup VPNN-Recovery-Backup.enc --key-file recovery.key --address 89.125.120.163 --apply
```

При новом IP укажи новый публичный IPv4. Сценарий проверяет snapshot/checksums/формат, ставит зависимости, создаёт собственные аккаунты/службы, сохраняет исходные ключи устройств/подписи, обновляет точные IP-поля профилей, поднимает HTTPS, DNS/VK и защиту SSH (3 ошибки, 30 дней), получает/настраивает продление сертификата. Повторный запуск того же восстановления продолжает незавершённую установку; завершённый запуск только проверяет активность служб. Параметры другого восстановления не перезаписывают существующий маркер.

Сценарий отказывается применять восстановление поверх действующего KIT/VPNN. Открывает необходимые правила UFW, но не включает выключенный UFW автоматически. Для ACME домен должен реально указывать на этот адрес; после смены IP дождись DNS. Прежние кэшированные VK-профили должны получить обновлённые настройки; DNS продолжает использовать делегированный домен.

**Чистый apply после переустановки ОС пока не проверен.** Это кандидат процедуры восстановления, а не основание стирать рабочую систему. Сценарий восстанавливает собственный VPNN DNS/VK/control; KIT/x-ui, сторонние профили и прежний отдельный iPhone-стек в его область не входят. При первой проверке возможна доработка дистрибутивных/systemd/certbot особенностей.

Для одной безопасной распаковки без установки можно использовать recovery.py --backup … --key-file … --destination /root/vpnn-restored; целевой staging-каталог не должен существовать.
